# Read-only server discovery

Discovery inspects only injected home/config roots or one selected absolute file. It reads Claude strict JSON, Codex TOML and OpenCode JSON/JSONC, rejects duplicate keys and applies a four-MiB read limit. JSONC permits comments and trailing commas only; JSON5 extensions stay disabled. Failed default sources remain visible beside healthy sources. Discovery never runs packages, commands, helpers, login or network requests, and never copies source credentials.

The supported local grammar is deliberately narrow: `npx` with optional `-y`/`--yes` and one literal package/version; `uvx` with one literal package or `package==version`; node/python with one absolute script path; or an absolute direct executable without arguments. The documented Filesystem package may include absolute directory arguments, and Time may include literal `--local-timezone=` arguments. Unknown arguments, helpers, interpolation and execution fields produce blocked rows. Literal HTTP/SSE records return only transport, origin and observed header names; URLs with user information, query parameters or fragments remain blocked. Original remote paths and header/environment values never appear in discovery output.

The backend-only installation capture reads and validates a selected source once when its preparation starts. It retains supported launch settings and local credential references, discarding all imported environment/header values. Successful saved source associations are reused before capture, so later source edits cannot silently update an existing installation. This is source implementation, with real installation/connection behavior unverified; it does not reproduce client configuration layering or project inheritance.

Remote import currently recognizes the public endpoint paths `/mcp`, `/sse` and `/api/mcp` (with optional trailing slash), plus Linear's documented `mcp.linear.app/mcp/readonly`. Unknown path layouts remain unsupported because arbitrary path segments may be credentials. Query strings, fragments and user information remain unsupported. Capture stores the parsed canonical URL for those recognized endpoints, never unclassified original path text. This is a compatibility limit, not a claim that every custom remote endpoint is unsafe or that all credentials occur in queries. Additional public endpoint layouts need a supported source profile before import; no new public API field or path-secret migration is added.
