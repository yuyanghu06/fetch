# Read-only server discovery

Discovery inspects only injected home/config roots or one selected absolute file. It reads Claude strict JSON, Codex TOML and OpenCode JSON/JSONC, rejects duplicate keys and applies a four-MiB read limit. JSONC permits comments and trailing commas only; JSON5 extensions stay disabled. Failed default sources remain visible beside healthy sources. Discovery never runs packages, commands, helpers, login or network requests, and never copies source credentials.

The supported local grammar is deliberately narrow: `npx` with optional `-y`/`--yes` and one literal package/version; `uvx` with one literal package or `package==version`; node/python with one absolute script path; or an absolute direct executable without arguments. The documented Filesystem package may include absolute directory arguments, and Time may include literal `--local-timezone=` arguments. Unknown arguments, helpers, interpolation and execution fields produce blocked rows. Literal HTTP/SSE records return only transport, origin and observed header names; URLs with user information, query parameters or fragments remain blocked. Original remote paths and header/environment values never appear in discovery output.

The backend-only installation capture reads and validates a selected source once when its preparation starts. It retains supported launch settings and local credential references, discarding all imported environment/header values. Successful saved source associations are reused before capture, so later source edits cannot silently update an existing installation. This is source implementation, with real installation/connection behavior unverified; it does not reproduce client configuration layering or project inheritance.

Remote import currently recognizes the public endpoint paths `/mcp`, `/sse` and `/api/mcp` (with optional trailing slash), plus Linear's documented `mcp.linear.app/mcp/readonly`. Unknown path layouts remain unsupported because arbitrary path segments may be credentials. Query strings, fragments and user information remain unsupported. Capture stores the parsed canonical URL for those recognized endpoints, never unclassified original path text. This is a compatibility limit, not a claim that every custom remote endpoint is unsafe or that all credentials occur in queries. Additional public endpoint layouts need a supported source profile before import; no new public API field or path-secret migration is added.

At first capture, an explicit Codex `tool_timeout_sec` seeds Fetch's per-server `execution.default_timeout_ms` after conversion from seconds to milliseconds; positive fractional seconds are supported only at whole-millisecond precision. An explicit scalar OpenCode `timeout` seeds the same Fetch setting directly in integer milliseconds for the supported flat server-entry format. The [Codex documentation](https://learn.chatgpt.com/docs/extend/mcp) defines its tool setting in seconds; [OpenCode documentation](https://opencode.ai/docs/mcp-servers/) defines the scalar in milliseconds, and [the inspected v1.19.4 source](https://github.com/anomalyco/opencode/blob/v1.19.4/packages/opencode/src/mcp/index.ts) passes that per-server value into tool execution through `requestTimeout`/`MCP.tools`. These are imported client wait preferences, not claims about a provider's intrinsic whole-call limit, so no five-second allowance or reported-tool-limit metadata is added.

The captured duration must be a finite positive whole number of milliseconds no greater than 86,400,000 (24 hours). Missing or unsupported source preferences use Fetch's 120,000-millisecond fallback. A malformed, zero, negative, overflowing, sub-millisecond or out-of-range value in either supported preference makes that source row invalid and prevents a fresh capture; it is not silently replaced. Other harness fields, startup/catalog budgets, OpenCode's newer nested timeout schema, descriptions, arbitrary MCP metadata and model arguments are not used as execution defaults. Successful import reuse happens before capture and preserves saved Fetch settings; changing the source later does not reset them. This mapping was implemented from read-only official documentation/source research; no parser, build, validator, service or test was run.

For the flat OpenCode format, the inspected call path is `requestTimeout` → `MCP.tools` → [the session's `convertTool` call](https://github.com/anomalyco/opencode/blob/v1.19.4/packages/opencode/src/session/tools.ts) → [`client.callTool` options](https://github.com/anomalyco/opencode/blob/v1.19.4/packages/opencode/src/mcp/catalog.ts). That adapter resets its own timer on progress. Fetch copies the configured duration as its own initial wait preference and applies Fetch's selected absolute deadline from dispatch; available progress does not extend it. This is neither an observed upstream maximum nor a promise to reproduce another client's timer behavior.

Railway's documented HTTPS endpoint at the root of mcp.railway.com is a known
remote profile alongside the existing MCP/SSE paths. This allows the official
remote import without rewriting its URL; existing rejection of credential-bearing
URLs, query/fragment data and unknown endpoint profiles remains. No connection
was made to inspect this profile.
